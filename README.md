# Детектив Алматы — скелет MVP

Технический скелет проекта по мотивам техдизайн-документа: Next.js + Supabase,
REST-стек без WebSocket/Mapbox. Контента (сюжет, персонажи, улики) здесь
намеренно нет — только рабочая архитектура.

## Быстрый старт

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатный тариф хватит на старте).
2. В SQL Editor выполните `supabase/schema.sql` — это создаст все таблицы и RLS-политики.
3. Скопируйте `.env.example` → `.env.local` и заполните ключи из Project Settings → API.
4. Установите зависимости и запустите:
   ```bash
   npm install
   npm run dev
   ```
5. Откройте http://localhost:3000 — увидите пустой каталог дел (пока нет строк в `cases`).

## Структура проекта

```
app/
  page.tsx                        — каталог дел (главная)
  game/[sessionId]/page.tsx       — экран локации/допроса (скелет UI)
  api/
    games/create/route.ts         — создание партии из оплаченного билета
    games/[sessionId]/state/      — текущее состояние (только discovered_*)
    games/[sessionId]/travel/     — переход между локациями (+20 мин)
    games/[sessionId]/dialogue/   — допрос по теме (+5 мин, открывает reveals)
    games/[sessionId]/accuse/     — финал: проверка улик + подсчёт очков
    payments/webhook/             — заглушка вебхука оплаты (Kaspi/эквайринг)
lib/
  supabaseAdmin.ts                — серверный клиент (service role, вся игровая логика)
  supabaseClient.ts               — клиентский клиент (только auth в браузере)
  scoring.ts                      — формула очков и стоимость действий в минутах
types/game.ts                     — типы, зеркалящие схему БД
supabase/schema.sql               — полная схема БД с комментариями и RLS
```

## Как добавить первое дело (пока нет админки)

Админ-панель сознательно не входит в MVP (см. техдок, разд. 6) — на старте
дело заливается напрямую через Table Editor в Supabase или SQL-инсертами:

1. Добавить строку в `cases` (пока без `start_location_id`).
2. Добавить локации в `locations` с `case_id` этого дела.
3. Обновить `cases.start_location_id` на id стартовой локации.
4. Добавить `characters`, `evidence`.
5. Для каждого персонажа — темы допроса в `dialogue_topics` и ответы в `dialogue_responses`.
   В `reveals` каждого ответа перечислить id того, что этот ответ открывает.
6. Добавить `accusation_questions` с `required_evidence_ids` для финала.
7. Проставить `cases.is_published = true`, когда дело готово.

## Известное ограничение скелета

`package.json` зафиксирован на Next.js 14.2.35 (последний патч в линейке 14.x на момент
сборки). `npm audit` может показывать открытые advisories в самой линейке 14.x
(в основном про Image Optimizer, i18n-middleware и WebSocket upgrade — вы это не используете).
Перед реальным продакшен-деплоем проверьте `npm audit` и актуальную рекомендованную
версию на [nextjs.org/blog](https://nextjs.org/blog) — возможно, стоит перейти на 15.x/16.x.

## Что дальше (не входит в этот скелет)

- Полноценный UI допроса конкретного персонажа (сейчас это упрощённая заглушка
  в `app/game/[sessionId]/page.tsx` — см. комментарий в коде).
- Auth-обвязка (логин/регистрация игрока через `supabaseClient.ts`) и защита
  API-роутов проверкой владельца сессии.
- Реальная интеграция с Kaspi Pay/эквайрингом вместо заглушки webhook.
- Экран покупки → создания партии (`POST /api/games/create`).
- Плейтест на живых людях перед релизом (см. чек-лист запуска).
